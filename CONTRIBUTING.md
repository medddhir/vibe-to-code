# Contributing to Vibe to Code

Thank you for helping more people move from guessing to understanding.

## Good first contributions

- Fix a typo or unclear explanation
- Add a beginner-friendly example
- Improve an exercise or mastery check
- Report an accessibility problem
- Propose a lesson for the published roadmap

## Before you begin

1. Search existing issues so the work is not duplicated.
2. Open an issue for a large course, feature, or design change.
3. Keep each pull request focused on one clear improvement.

## Lesson principles

Every lesson should:

- explain one main idea in plain language;
- connect the idea to something familiar;
- show a small working example;
- ask the learner to predict before revealing an answer;
- include a debugging or editing task;
- end with a clear mastery check;
- avoid assuming prior technical knowledge.

Write for an intelligent beginner. Simple does not mean inaccurate, and friendly does not mean childish.

## Local setup

```bash
git clone https://github.com/medddhir/vibe-to-code.git
cd vibe-to-code
npm install
npm run dev
```

Before opening a pull request, run:

```bash
npm run check
```

## Pull requests

- Use a short, descriptive title.
- Explain what changed and why it helps the learner.
- Include screenshots for visible interface changes.
- Link the related issue when one exists.
- Confirm that you tested the affected pages.
